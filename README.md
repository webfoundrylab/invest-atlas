# Invest Atlas

投資信託・ETFを中心に、NISA、個別株、経済・市場、資産形成まで扱う日本語の投資情報サイトです。

## 運営方針
- 無料の GitHub Pages を基本とし、収益発生前に有料サービスや広告費を導入しない。
- 公的機関、取引所、運用会社、企業の一次資料を優先する。
- 記事には必要な情報確認日、出典、リスク、費用を明記する。
- 過去の実績と将来の成果を混同せず、特定の投資判断を断定的に勧めない。
- 広告・アフィリエイトを導入した場合は適切に明示し、報酬の有無で比較結果を歪めない。

## 公開・デプロイ
- 公開URL: https://webfoundrylab.github.io/invest-atlas/
- GitHub Pages を GitHub Actions からデプロイする。
- `.github/workflows/pages.yml` がビルド・検証・デプロイを実行する。
- 検証が失敗した場合は公開処理を止める。Actionsの成功と、公開ページの実ブラウザ確認は区別する。

## 主要ファイルの役割
- `PROJECT-STATE.md`：現在の状態、実施履歴、未解決課題、次の作業。進捗管理の正本。
- `EDITORIAL-GUIDELINES.md`：記事編集、内部リンク、文言の明確さ、金融情報の編集基準。
- `article-index.json`：記事台帳の単一情報源。記事タイトル、概要、カテゴリ、タグ、状態、サムネイル、関連記事候補などを管理。
- `scripts/build-site.py`：カテゴリページ、サイトマップ、関連記事候補などの生成処理。
- `scripts/validate-content.py`：記事ファイル、カテゴリ、関連記事候補、サイトマップなどの検証。
- `index.html`：トップページ、検索・カテゴリ・タグによる記事絞り込み。
- `assets/`、`thumbnails/`：共通レイアウト資産と記事サムネイル。
- `robots.txt`、`sitemap.xml`：クローラー向け設定。ビルド時に生成・同期される内容は生成スクリプトを正とする。

## 記事台帳とカテゴリ
- `article-index.json` の `categories` は `children` で階層を定義する。
- 記事には `category`（大カテゴリ）、`subcategory`（中カテゴリ）、必要な場合のみ `topic`（小カテゴリ）を設定する。
- `tags` はカテゴリを横断する検索用テーマ。表記をできるだけ統一する。
- 記事台帳には `slug`、`title`、`summary`、`status`、`tags`、必要に応じて `thumbnail`、`related`、公開日・更新日を登録する。
- カテゴリや記事を追加する前に、既存の分類・記事との重複を確認する。

## トップページの検索・絞り込み
- キーワード、カテゴリ階層（大・中・小）、タグを組み合わせて記事を絞り込める。
- キーワード検索は複数語に対応し、OR（いずれか）とAND（すべて）を切り替えられる。対象はタイトル・概要・タグ。
- タグはモーダルで検索・複数選択・解除ができ、タグ条件もOR/ANDを切り替えられる。
- カテゴリは親階層の選択に応じて下位候補を表示する。各階層に「すべて」を用意し、下位条件だけ解除できる。
- 記事は更新日の新しい順で表示し、公開日・更新日を併記する。
- モバイルでは検索条件やカテゴリナビゲーションを開閉できる構成とする。

## サムネイル制作ルール
- 記事サムネイルは `thumbnails/<slug>.svg` に保存し、`article-index.json` の `thumbnail` に明示登録する。
- 画像仕様・共通レイアウト・配色・セーフエリア・モバイル確認の基準は [THUMBNAIL-GUIDELINES.md](THUMBNAIL-GUIDELINES.md) を参照する。
- 図柄の背後に置く白抜きの大きな円は使用しない。PC用は16:9の横長で作成し、モバイルでは無理な正方形切り抜きを行わない。

## 記事ページ・生成処理
- `scripts/build-site.py` はカテゴリ別記事一覧を `categories/` 以下に生成する。
- 記事ページにカテゴリへのパンくずとカテゴリツリーを追加し、カテゴリ一覧と共通のレイアウトを利用する。狭い画面ではナビゲーションを折りたたむ。
- 記事のないカテゴリページは `noindex` とし、公開記事のあるカテゴリページのみサイトマップに登録する。
- `sitemap.xml` と `related-articles.json` はビルド時に生成される。
- `related-articles.json` は関連記事候補の管理データであり、本文の関連記事リンクを自動的に適切な場所へ挿入するものではない。

## 内部リンクと編集基準
関連記事リンクは、読者が次に知りたくなる説明の近くに手動で配置する。リンク先が存在するだけでなく、文言だけで遷移先の内容が伝わり、本文の文脈とリンク先が一致していることを確認する。曖昧な「こちら」「詳しくはこちら」だけのリンクは避ける。特定の章が関係する場合は、必要に応じてその見出しへ直接リンクする。記事末尾に関連記事を一括で並べる方式は使わない。

詳細な基準と点検チェックリストは [EDITORIAL-GUIDELINES.md](EDITORIAL-GUIDELINES.md) を参照する。

## 新記事の追加手順
1. `EDITORIAL-GUIDELINES.md` を確認し、既存記事との重複と記事の役割を整理する。
2. HTML記事を作成し、公式情報、出典、情報確認日、リスクを確認する。
3. `article-index.json` に記事情報、カテゴリ、タグ、必要な関連記事候補を登録する。
4. 関連記事リンクを文脈に沿って配置し、文言の明確さと遷移先の具体性を確認する。
5. HTML構造、内部リンク、アンカー、メタ情報、canonical、画像、サイトマップを確認する。
6. GitHub Actionsの検証・デプロイ結果を確認する。公開画面の実表示を確認していない場合は未確認と記録する。

## 管理
作業開始前にGitHubの最新状態と `PROJECT-STATE.md` を確認する。過去の会話や記憶だけで現在の状態を判断しない。作業後は変更ファイル、コミット、Actionsの結果、公開確認の有無、未解決課題を `PROJECT-STATE.md` に記録する。
